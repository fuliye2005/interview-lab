# Interview Lab 项目记忆区

更新时间：2026-08-18

这不是用户数据或密钥文件，只记录产品不变量、实现证据、未验证风险和下一检查点。任何继续工作前先读取本文件，并以当前工作树、测试输出和 release 构建为准。

## 产品不变量

- Interview Lab 是面向售前、解决方案、实施交付、运维支持、技术项目管理等非开发技术岗位的本地优先 Windows 面试工作台。
- 主窗口负责配置，悬浮面试台负责一整场测试，会话档案库负责一面、二面、三面和复盘。
- 每次启动测试创建一个独立会话；每次提交问题追加到同一会话；历史会话通过父会话关系承接。
- API Key 不进入日志、会话记录、配置预览或浏览器 localStorage；桌面端凭证只进 Stronghold。
- 小改动不单独跑全量测试；每个功能检查点集中验证，并进行一到两轮轻量对抗审查。

## 当前工作树

当前分支为 `main`。`d58c21c` 之后存在未提交的“数据安全与恢复”改动，以及回答栏布局强制顺序修复：

- 安全备份 JSON 导出/导入，导出内容明确排除 API Key，导入保留本机已有凭证。
- 存储诊断：SQLite/localStorage、数据版本、Stronghold、备份数量和 SQLite quick check。
- 浏览器预览保存设置时只写脱敏配置，不再把 Key 写入 localStorage。
- 回答面板已改为明确的三行 grid：标题、操作栏、回答内容；操作栏不再依赖 flex `order`，避免小窗口下被内容挤到面板底部。
- 实时增量转写与最终问题框保持分栏：前者是只读的 ASR 临时状态，后者是可编辑、清空并提交给模型的最终问题，不能合并。
- 会话控制条和两栏输入区前置，上下文、回答框架、快捷键等次要信息下沉到次级区域；回答生成时悬浮窗可后台预热但保持隐藏和主窗口焦点，只有用户主动点击“打开悬浮窗”才显示并切换焦点。

这些未提交改动在提交前必须重新跑类型检查、测试、前端构建和 release 构建。

## 第一性原理审查清单

- 状态是否有唯一可信来源？桌面配置/会话来自 SQLite，密钥来自 Stronghold。
- 空配置、空回答、失败记录是否会污染上下文或生成虚构事实？
- 上下文超限时是否保留固定事实和最近轮次，并显示实际发送数？
- 最小窗口、窗口缩放、悬浮窗隐藏/重开后，关键操作是否仍可见？
- 导入、迁移、异常退出时，是否会覆盖现有配置或泄露 Key？
- 每个检查点只做一到两轮针对高风险路径的对抗审查，不把小改动扩大成无边界测试。
